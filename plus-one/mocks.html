Fire the prompt on top of the RSVP confirmation

This is the moment of highest intent. The user just committed to a time and place and is already picturing who they'd go with. Same trigger ClassPass uses, but the ask is "bring someone to this," not "join the app."

dev notes
  • Trigger: rsvp.created, shown once per RSVP as a bottom sheet, not a full-screen interstitial.
  • Copy pulls live numbers: going count and spots left. Fall back to "bring someone" if the event has no cap.
  • "maybe later" dismisses for this event. A second nudge is fine 24h before the event if no plus-one was sent.
  • Skip the prompt if the user arrived via someone else's invite link. They are the plus-one already.

Don't split "invite a member" from "invite a friend"

ClassPass has two separate flows. Pace should have one list. People already on Pace sort to the top with a badge. Everyone else is a normal contact. The user picks names, not channels.

dev notes
  • Requires contacts permission. Match on hashed phone numbers server-side. Do not upload raw contact lists.
  • Members: in-app invite record + push notification. Deep-links straight to the event with RSVP sheet open.
  • Non-members: open the native SMS composer (MFMessageComposeViewController on iOS) with prefilled body. One composer per recipient, or one group text if 2+ are selected. Never send SMS from your own number on their behalf.
  • Each invite gets its own id so the "with Niki" attribution in step 05 can be exact, not inferred from timing.
data model
invites: id, event_id, inviter_id, invitee_phone_hash, invitee_user_id (nullable), channel (push|sms), sent_at, opened_at, rsvp_id (nullable)

The link is the event, not the app

ClassPass's text says "share this spot" but the preview reads "Join your friends at ClassPass" and lands on a signup page. Pace's preview is the event itself: photo, name, time, venue, who's going. The friend is saying yes to Saturday, not to a download.

dev notes
  • Prefilled body is lowercase, first person, names the event and time, ends with a question. Editable before send.
  • Link format: pace.app/e/{slug}?by={user_id}&i={invite_id}. Keep it short so it fits one line.
  • Event page serves Open Graph tags: og:image = event photo (1200×630 crop), og:title = name · day · time, og:description = venue · N going · {inviter first name}'s in. Render these server-side so iMessage, WhatsApp and Instagram DMs all unfurl.
  • Going count in the preview should be live at unfurl time, cached ≤5 min.

Web RSVP with a phone number. The app comes after.

If the link opens the App Store, most invitees drop. Let them RSVP on the web with a phone number, then pull them into the app for the things that need it: seeing who's going in full, messaging, the next event.

dev notes
  • Public, server-rendered event page. No auth to view. Attendee list shows first names and initials only until the viewer is logged in.
  • Flow: phone → SMS one-time code → RSVP created with referred_by and invite_id from the URL → confirmation SMS with event details and an app deep link.
  • Create a lightweight user record on web RSVP. When they install later, phone-number login merges it, so the referral edge and the RSVP survive.
  • If the app is installed, Universal Link / App Link opens the event in-app with the same query params.
  • Hide the "Niki invited you" card if by is missing or the inviter is not RSVP'd.

05 · close the loop: "with Niki" on the list

Show the connection, and tell the inviter it worked

The "with Niki" tag is the payoff for both sides. The invitee sees a familiar name before walking in. The inviter gets a push the moment the friend RSVPs. That push is what makes people invite again next week.

dev notes
  • Tag renders when rsvp.referred_by is set and the referrer is also RSVP'd. If the inviter cancels, drop the tag but keep the referral edge.
  • Push to inviter on invitee RSVP: "{first name}'s in". Deep-link to the attendee list.
  • "bring someone else" reopens the picker from step 02 with already-invited contacts hidden.
  • Treat referred_by as a permanent graph edge on the user, separate from the per-event RSVP. It feeds "3 of your friends are going this week" later.
metrics that say whether the loop works
invites sent ÷ RSVPs · invite → page view · page view → RSVP · share of new users with referred_by set · hours from invite to invitee RSVP · inviter repeat rate next event

deliberately not in v1

  • Cash or credit rewards. The motive is "don't go alone," not money. Access to invite-only events can come later.
  • In-app chat for invites. Texts already work and need no inbox.
  • Contact sync at onboarding. Ship the picker first, then decide.
  • Group-text to many at once. One or two names per RSVP is the use case.
